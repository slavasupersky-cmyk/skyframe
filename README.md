# Конфигураторы домов

## Studio — основной движок (с октября 2026)

Конфигуратор в духе автомобильных: слева большая картинка дома, справа выбор планировки,
материалов и комплектации, цена внизу всегда на виду. Картинка сама переключается на то,
что человек сейчас выбирает: планировку, фасад, интерьер. Работает на телефоне, планшете и компьютере.

Живая версия Mashko: `d/mashko/`.

```
studio/                 движок — один на всех заводов (studio.js, studio.css, page.html, шрифт)
brands/<завод>/         всё, что относится к заводу — правится руками
  brand.json            название, цвет, логотип, контакты, тексты, пакеты комплектации;
                        pin — какие модели идут первыми; home — преимущества, технология и шаги на главной;
                        intro.focus — какая часть обложки остаётся в кадре на телефоне
  models.csv            модели: id, name, description
  variants.csv          планировки и цены — одна строка на планировку
  materials.csv         образцы: фальц, фасад, терраса, отделка внутри
  media/<модель>/       картинки модели
  media/_shared/        общие картинки (запасные для всех моделей)
  build/                собирается автоматически — не трогать
tools/studio_build.py   сборка: таблицы + картинки → страница
```

### Как поменять цену или добавить планировку

1. Открыть `brands/mashko/variants.csv` на GitHub → карандаш «Edit» (или скачать и открыть в Excel/Numbers).
2. Поправить число или добавить строку. Колонки: `model, variant, area_m2, label, kit_factory, windows, seam,
   foundation, mount, crane, finish, mep`. Пустая цена = «индивидуально», в итог не входит.
3. Commit changes. Через 1–2 минуты страница пересоберётся сама (GitHub Actions → studio-build).

Домокомплект на сайте = `kit_factory + windows + seam`, «Монтаж и кран» = `mount + crane`
(это задаётся в brand.json → base и packages).

### Как добавить модель

1. Строка в `models.csv`: `id` латиницей (например `zenit`), название, описание.
2. Строки в `variants.csv` с этим `model`.
3. Папка `brands/mashko/media/zenit/` с картинками (см. ниже).

Порядок моделей считается сам — от самой доступной к самой дорогой.

### Картинки: имена файлов

| Файл | Где показывается |
| --- | --- |
| `cover.jpg` | карточка в каталоге и запасной кадр снаружи |
| `ext-evening.jpg` | карточка в каталоге (если есть — вместо cover) |
| `plan-<variant>.jpg` | планировка, `<variant>` — из variants.csv |
| `ext-hero-<id фальца>.jpg` | главный кадр в выбранном цвете фальца, например `ext-hero-ral7016.jpg` |
| `ext-facade-<id>.jpg`, `ext-terrace-<id>.jpg` | крупный план фасада и террасы |
| `ext-side.jpg` | вид сзади |
| `int-<id отделки>.jpg` | интерьер: `int-raw`, `int-light`, `int-warm`, `int-graphite` |

Формат 3:2, jpg или png любого размера — тяжёлые файлы сборка сожмёт сама.
Нет нужного кадра — покажется запасной, с честной подписью. Промты для генерации — в документе
«Mashko — промты для картинок конфигуратора».

### Новый завод

Скопировать `brands/mashko` в `brands/<новый>`, поменять brand.json (название, цвет, логотип, контакты,
`output` — куда класть страницу), таблицы и картинки. `python3 tools/studio_build.py` соберёт все заводы.

## Старые версии (v1–v4, архив)


Один движок, сколько угодно дилеров. Данные лежат отдельно от кода, страницы собираются скриптом.

```
content/           данные: таблицы цен и картинки — это правите вы
engines/           интерфейсы: v4 / classic / steps / wizard — это правлю я
build.py           сборка: content + engine → готовая страница
v4/                ОСНОВНАЯ ВЕРСИЯ — витрина + конфигуратор
index.html         результат сборки бренда skyframe (не правьте руками)
d/<дилер>/         результат сборки дилерского пака
```

## Версии интерфейса

| Папка | Движок | Что это |
|---|---|---|
| **`v4/`** | **`v4`** | **основная.** Герой → два слайда про технологию → плитка моделей → пошаговая сборка на весь экран |
| `/` | `classic` | первая версия, длинная страница со всем сразу |
| `v2/` | `steps` | архив: полноэкранные шаги со снапом |
| `v3/` | `wizard` | архив: кадр слева, мастер справа |

Архивные версии пока собираются вместе с остальными — цены в них не расходятся
с основной. Когда перестанут быть нужны, достаточно удалить их пак из `content/`.

### Из чего состоит v4

Одна страница, скролл сверху вниз:

1. **Герой** — кадр во весь экран, цифры каталога, кнопка в конфигуратор
2. **Технология** — семь слоёв конструкции и разрез (взято из презентации)
3. **Процесс** — три фотографии стройки и пять шагов со сроками
4. **Объекты** — реальные дома производства
5. **Каталог** — плитка моделей; клик открывает конфигуратор поверх страницы

Конфигуратор устроен так же — скроллом сверху вниз: дом → планировка →
экстерьер → комплектация → интерьер → заявка. Цена висит внизу всё время,
липкая полоска сверху показывает, где вы сейчас, и позволяет перепрыгнуть.

Тексты разделов 2–4 лежат прямо в разметке `engines/v4.html` — обычный HTML,
правится без программирования. Фотографии к ним — в `content/<бренд>/site/`,
имя файла и есть ключ: `razrez.jpg`, `process-1..3.jpg`, `obj-1/3/4.jpg`.
Положили файл с тем же именем — картинка заменилась. Файла нет — блок с ним
просто не показывается, страница не ломается.

## Как поменять цену

1. Откройте `content/skyframe/catalog.xlsx`, лист **catalog**
2. Поправьте нужную ячейку
3. `python3 build.py`
4. Закоммитьте и запушьте

Через минуту цена на сайте новая. Больше ничего трогать не нужно.

## Как добавить модель

1. Создайте папку `content/skyframe/models/<ключ>/` — ключ латиницей, например `zenit`
2. Положите внутрь:
   - `cover.jpg` — главный кадр модели
   - `silhouette.png` — контур на прозрачном фоне
   - `plan-<ключ конфигурации>.jpg` — по файлу на каждую конфигурацию
3. Допишите строки в `catalog.xlsx` — по строке на конфигурацию
4. `python3 build.py`

**Ключи связывают таблицу с файлами.** Строка `model=zenit, config=42` ищет файл
`models/zenit/plan-42.jpg`. Если файла нет — сборка честно скажет об этом и остановится.

Порядок моделей на странице считается сам: от дешёвого домокомплекта к дорогому.

## Как завести нового дилера

1. `content/<дилер>/brand.json` — название, телефон, цвет, какой движок, куда собирать
2. `content/<дилер>/catalog.xlsx` — свои цены и названия
3. Картинки: либо свои в `content/<дилер>/models/` и `site/`, либо
   `"media_from": "skyframe"` в brand.json — тогда возьмутся чужие,
   без дублирования мегабайтов
4. `python3 build.py`

Пример уже есть: `content/mashko/` — те же дома, но заводские названия, свой телефон
и оранжевый акцент. Собирается в `d/mashko/`.

### brand.json

```json
{
  "key": "skyframe",
  "title": "Skyframe",
  "tagline": "модульные дома",
  "phone": "+7 (499) 647-76-80",
  "phone_href": "tel:+74996477680",
  "catalog_pdf": "katalog-skyframe.pdf",
  "engine": "classic",
  "output": ".",
  "accent": "#c9f24e"
}
```

`engine` — какой интерфейс собрать: `v4` (основной), `classic` (длинная страница),
`steps` и `wizard` (архивные).
`output` — куда положить `index.html` относительно корня репозитория.

## Колонки catalog.xlsx

| Колонка | Что это |
|---|---|
| Ключ модели | латиницей, он же имя папки в `models/` |
| Название | как видит клиент |
| Заводское имя | мелкой строкой под названием |
| Ключ конфигурации | латиницей, он же хвост имени файла `plan-…jpg` |
| Подпись | как видит клиент: «82 м² · с сауной» |
| м² | площадь, число |
| Домокомплект | внешний тёплый контур — входит всегда |
| Монтаж | сборка бригадой |
| Фундамент | винтовые сваи |
| Чистовая отделка | полы, стены, санузел |
| Инженерия | электрика, вода, отопление |

Цены в рублях, без пробелов и знака рубля. Пустая ячейка считается нулём.

## Проверка без сборки

```
python3 build.py --check
```

Покажет недостающие картинки и незаполненные цены, ничего не записывая.
